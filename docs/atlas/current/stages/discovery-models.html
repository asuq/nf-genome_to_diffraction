Documentation / Workflow stage
Stage 03

Find and prepare protein structure models

For every supplied protein sequence, search local structure databases for related experimental structures or explicitly mapped predictions, then convert valid coordinates into models that Molecular Replacement can test.

Current maturity: HPC-qualified

Visible limitation. A completed no-hit means that one search route found no model under its stated criteria; it is not an execution failure and does not prove the protein is absent.

Purpose

Produce a checked set of protein structure models while keeping the search result, the prepared coordinate file, and the supplied protein identity distinct.

Inputs

  • Groups of identical sequences from the supplied protein list
  • Qualified local PDB SEQRES database for MMseqs2
  • Qualified local PDB100 database plus the ProstT5 model for Foldseek
  • Optional explicit protein-to-AlphaFold-DB accession map
  • Installed Gemmi runtime and, for predicted models, the verified Phenix runtime

Outputs

  • MMseqs2 and Foldseek hit, no-hit, and ineligible records
  • Downloaded or locally registered coordinate sources with checksums
  • Prepared protein structure models linked to the supplied protein sequence
  • A complete registry that also records proteins with no eligible model

Decisions and statuses

  • MMseqs2/PDB SEQRES: keep hits with E-value at most 1e-5 and at least 50% query coverage
  • ProstT5/Foldseek/PDB100: keep hits with E-value at most 1e-3 and at least 50% query coverage
  • Retain at most three normalised hits per protein from each local PDB search route
  • Use AlphaFold DB only when an explicit accession map connects it to the supplied protein
  • Keep ESM Atlas disabled unless remote sequence submission is explicitly enabled
  • Reject missing chains, checksum changes, sequence mismatches, malformed coordinates, and unsupported multi-model inputs

Claim and failure boundaries

  • A database hit proposes a model; it does not prove which protein is in the crystal
  • Every reportable identity must come from the supplied protein list
  • PDB models are cleaned with Gemmi by retaining the mapped polymer chain and removing non-polymer atoms and hydrogens
  • Exact predicted models are confidence-pruned with phenix.process_predicted_model
  • Normal analysis runs use prepared, versioned databases and never silently rebuild them
Run commands and implementation links

Use commands only with the reviewed configuration, immutable source, and owned inputs for the intended site. Placeholders are deliberate.

nf-gtd-hpc-test database-readiness
pixi run --locked phase3-foldseek-batch-stub
