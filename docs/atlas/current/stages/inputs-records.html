Documentation / Workflow stage
Stage 01

Provide organism, sequence, annotation, and diffraction inputs

Supply the biological source, the proteins that may be tested, their genome and annotation context when available, and the measured diffraction data.

Current maturity: implemented

Visible limitation. The workflow records file checksums so results cannot silently switch to a changed input file.

Purpose

Keep every biological and diffraction input separate and make sure later steps cannot mix files, organisms, or crystals.

Inputs

  • Scientific species name plus strain/assembly identity — required to resolve the correct genome, annotation, and proteome, but not yet dedicated manifest fields
  • Protein FASTA (.faa) — required
  • Annotation provider and version — required
  • Genome FASTA (.fna) — optional
  • GFF/GBFF and protein-to-locus files — optional
  • Diffraction MTZ file and crystal name — required
  • Molecular-weight observations — optional
  • Run settings and installed reference-database descriptions

Outputs

  • Resolved genome, annotation, and proteome source identities
  • A checked record of the biological source and protein sequences
  • Optional genome and annotation context retained when supplied
  • A checked record of each diffraction file
  • A record of the exact inputs used by every later step

Decisions and statuses

  • Use one annotation source for the protein list
  • Stop when a required file is missing, changed, duplicated, or malformed
  • Keep every possible gene location when two entries have the same protein sequence

Claim and failure boundaries

  • A structure found in an external database cannot add a new protein identity that was absent from the supplied list
  • Missing genome, annotation files, or molecular-weight evidence remains explicitly optional
  • Localisation evidence is derived internally from the protein FASTA with PSORTb and DeepTMHMM
  • The workflow trusts the supplied protein list; it does not predict genes or assign taxonomy
  • Species-to-genome/proteome source resolution and dedicated species/assembly fields are not yet implemented
  • A species may have multiple strains or reference assemblies, so exact source resolution requires strain or assembly identity in addition to the species name
Run commands and implementation links

Use commands only with the reviewed configuration, immutable source, and owned inputs for the intended site. Placeholders are deliberate.

pixi run --locked schema-check
pixi run --locked docs-atlas-check
