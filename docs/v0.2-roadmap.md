## v0.1 release boundary

v0.1 preserves the current single-component implementation and its exact known
limitations. The release notes must say:

- M6 scientific acceptance is held;
- the successful M6 Nextflow run is only orchestration evidence;
- the main MR path is single-component and still contains legacy sequential
  copy-placement behaviour;
- 7L6G placed three rather than six copies;
- two-component heteromer reconstruction is absent;
- several crystallographic propagation, Free-R, retry, cache-identity, and M6
  measurement issues remain in the tracked backlog; and
- the release is a research snapshot, not a production or automated-identity
  claim.

The release artefact is the tagged source, lock file, changelog, and release
notes. A general wheel/distribution guarantee is not required.

## v0.2 outcome

v0.2 succeeds when the software can do the following reproducibly on a known
control:

1. retain or obtain a placed A solution;
2. fix A in Phaser;
3. search for B;
4. retain B-specific TFZ and incremental LLG evidence;
5. write the combined A+B model and associated Phaser outputs; and
6. report a typed no-solution outcome without fabricating a component.

The first target is 6RTZ HisF/HisH with explicit `1A + 1B`. General genome-wide
partner discovery, automatic stoichiometry inference, and unknown crystals are
not required for the first success.

## Scientific rules retained from supervisor review

### Candidate evidence

- SDS-PAGE apparent molecular mass is the strongest initial component prior
  when available.
- Native PAGE oligomer information is a useful composition prior when
  available; missing gel data is neutral.
- Unit-cell/Matthews estimates guide plausible total mass but do not exclude
  high-solvent crystals. Solvent content near 80% is possible.
- Coverage and model quality rank candidates. They do not automatically exclude
  a protein because disordered or unfolded residues may be invisible.
- Moderate sequence identity is not an exclusion rule. A roughly 40%-identity
  homologue may still provide a useful MR model.
- Physically impossible compositions may be excluded. Weak priors and missing
  data may not be converted into false certainty.

Membrane/exported localisation filtering remains deferred until after the
heteromer milestone, as previously decided.

### Phaser search policy

- For a declared same-component copy count, ask Phaser to search for the
  requested copies jointly where practical.
- For heteromers, retain/fix the accepted A state and search for B.
- Primary evidence is `LLG > 100` and `TFZ > 10`.
- If no primary hit is found, run the fallback cohort at `LLG > 50` and
  `TFZ > 5`.
- Scores prioritise inspection; they are not proof of composition.
- For fixed-A partner searches, rank with B-specific TFZ and incremental
  `delta_LLG`, not the total child LLG dominated by A.
- Keep executed attempts and raw metrics even when they fail the current score
  cohort.

## Minimal v0.2 architecture

Do not begin with a general composition engine. Add only the records needed by
the running path:

- `ComponentSpec`: component label, sequence-group ID, model ID/path/checksum,
  and requested copy count;
- `CompositionSpec`: exactly A and B plus `n` and `m`;
- `SolutionState`: parent/fixed model, placed copies per component, Phaser
  metrics, coordinate/MTZ/log paths, and terminal status; and
- `PartnerSearchResult`: B-specific TFZ, incremental LLG, packing status, and
  combined-model evidence.

Reuse the existing Phenix runtime wrapper, sequence groups, models, MTZ
preflight, checksums, and Nextflow process style. Do not build a general DAG,
beam search, arbitrary-component schema, provider framework, or new scheduler
driver for the first control.

### P1 — Minimal fixed-A/one-B adapter

Status: implemented and focused-test green locally. Real 6RTZ Phenix
qualification remains open, so P1 is not yet accepted. The implementation is
deliberately restricted to `1A + 1B`; it does not add general composition or
Nextflow orchestration ahead of evidence from the direct control. The fixed
input preparer has run successfully against the checksum-frozen public 6RTZ
coordinate and structure-factor files and produced a preflight-readable MTZ;
only scheduled real-Phenix execution remains open.

Use known, checksum-reviewed control inputs. Do not depend on genome ranking.

- accept a placed/fixed A coordinate state;
- accept one B search model and the target sequence/composition;
- construct the Phaser command for fixed A + one B;
- parse B-specific TFZ and incremental LLG;
- retain combined coordinates, MTZ, log, command, and raw result; and
- emit hit, no-solution, tool-failure, and parse-failure states.

Gate: focused command/parser/failure tests and one real Phenix run using the
known 6RTZ parent/model pair.

### P2 — 6RTZ adapter-isolation smoke

- use an independently reviewed A parent so upstream candidate/model discovery
  cannot obscure partner-placement defects;
- place HisH as B with A fixed;
- inspect the combined model and retained Phaser evidence; and
- record the exact input checksums, Phenix version, command, and outcome.

Gate: correct A+B control placement or a narrowly diagnosed adapter defect.

### P3 — End-to-end 6RTZ

- obtain A through the existing component workflow;
- choose one retained A state explicitly;
- fix it and search B;
- preserve the composition review checkpoint; and
- run sequence-from-map only after composition review on approved alternatives.

Gate: one end-to-end `1A + 1B` result with no manual file substitution inside
the scheduled task.

### P4 — Explicit `nA + mB`

- allow explicit positive `n` and `m` values;
- search requested same-component copies jointly where the adapter supports it;
- fix the retained A state and search the requested B copies;
- keep a sequential fallback only as a rescue path; and
- report placed versus requested copies without calling packing alone
  scientific support.

Gate: 6RTZ `1A+1B` remains green and one known multi-copy heteromer exercises
`n>1` or `m>1` (preferred control: 3U7Q `2A+2B`).

### P5 — Minimal catalogue partner search

Only after the explicit controls work:

- enumerate B candidates from supplied catalogue sequence groups;
- order by remaining SDS band compatibility, native-PAGE/composition prior,
  combined Matthews plausibility, model quality, and structural diversity;
- retain missing-data candidates rather than silently excluding them;
- use a deterministic small cap (initially 25 B attempts per retained A state);
  and
- retain tested/untested counts and the reason for the cap.

Do not add localisation software in this milestone.

### P6 — Small control slice

Use the smallest set that detects obvious scientific failure:

- 6RTZ positive `1A+1B`;
- one second positive, preferably 3U7Q `2A+2B`;
- missing-B control;
- wrong-B control;
- homomer non-regression; and
- 9ECN three-component case as `unsupported_component_count`, while retaining
  any valid partial A+B placement without claiming a complete composition.

Gate: positives recover the expected component families, negatives do not make
false complete-composition claims, and the homomer route still runs.

### P7 — Experimental v0.2 release

Release v0.2 when P1--P6 run from a clean tagged source. The release may remain
experimental. It must list control outcomes and known limitations; it does not
wait for the deferred robustness backlog.

## Development loop

For each slice:

1. write one focused regression or command/parser test;
2. implement the smallest vertical change;
3. run only touched tests while iterating;
4. run one real Phenix control as soon as the adapter is runnable;
5. run the complete locked repository gate only at P2, P3/P4, and release
   boundaries;
6. use CI once per pushed milestone; and
7. use one fixed Marmic profile only after the local/adapter control passes.

Do not build a new general HPC monitoring framework. Reuse the reviewed wrapper
for any fixed remote smoke. Classify a real failure before editing.
