# Software v0.2 roadmap

## Purpose and authority

This roadmap defines the path from the preserved sequential single-component
prototype to a validated, bounded two-component research workflow:

\[
\mathrm{ASU}=nA+mB,\qquad A\ne B,\quad n,m\geq1
\]

It incorporates the supervisor decisions recorded in the screening discussion,
the current Nextflow/Slurm execution architecture, and every finding in the
[adversarial review](adverse-code-review-2026-08-17.md).

This document is a development plan, not permission to start heteromer code.
`AGENTS.md`, the schemas, examples, and the approved external handoff remain
authoritative in that order. The current M6 loop and v0.1 release must close
before v0.2 feature work starts.

The historical repository milestone called **Prototype 0.2** is distinct from
the future semantic software release **v0.2.0**. Historical M5/M6 evidence and
schema-v1 results must never be relabelled as v0.2 evidence.

M0--M5 and Prototype 0.2 remain accepted with the immutable limitation that
7L6G placed three rather than its declared six copies. Do not rerun, relabel,
hide, or reinterpret that result while developing v0.2.

## Current boundary and release decision

uses one-copy Phaser followed by sequential fixed-parent additions, the strict
`LLG > 50 OR TFZ > 5` ranking annotation, one unsplit confidence-pruned
predicted model, one cleaned experimental chain, and refinement after the MR
seed checkpoint.

The current two-case M6 Nextflow smoke may establish orchestration behaviour
only. The adversarial review found three P0 defects that make correct-family,
exact-false-assignment, and edge-control acceptance gates structurally unable
to measure what they claim. It also found a 29-catalogue fan-out defect and
cross-cutting cache, crystallographic, Free-R, and packing-support defects.

Therefore:

1. collect the current smoke unchanged and classify it as non-acceptance
   orchestration evidence;
2. submit no operational or leakage M6 scientific track until the stop-gate
   remediation below passes;
3. rerun M6 from a new immutable archive after remediation;

5. let the user publish the immutable v0.1 release; and
6. begin v0.2 edits only after a separate explicit start instruction.

If v0.1 is published before the stop gates are corrected, it must be labelled
an archival experimental snapshot with M6 held. Such a release does not open
Gate 1 and does not authorise heteromer implementation.

## v0.2 capability decisions

| Area | v0.2 decision |
| --- | --- |
| Identity universe | Retain all valid annotated CDS products. Exact duplicate sequences remain one sequence-equivalence group linked to every locus. |
| Localisation | Defer SignalP, DeepTMHMM, and automatic membrane/exported exclusion until after the heteromer milestone. Do not add annotation-string filtering. |
| Hard exclusion | Exclude only malformed or unusable sequences and physically impossible composition hypotheses. Missing models produce `deferred_no_model`. |
| SDS-PAGE | Use apparent monomer/polypeptide mass to define a strong/compatible first wave and a retained weak/mismatched fallback wave. Missing data are neutral. |
| Native PAGE | Accept apparent native mass with absolute uncertainty and use uncertainty-normalised oligomer/total-mass compatibility for ranking only. It never establishes ASU copy number. |
| Matthews | Retain the predeclared 10--90% solvent search window and up to four in-window hypotheses. Outside-window hypotheses are typed as deferred rather than called physically impossible. Extend the calculation to combined sequence-derived `nA+mB` mass. |
| Predicted models | Retain the confidence-pruned full model and add at most three compact-domain variants per source coordinate. |
| Experimental models | Retain the cleaned source chain and add one target-adapted `phenix.sculpt_ensemble` variant per mapping. |
| Accuracy and redundancy | Do not impose a sequence-identity cutoff; approximately 40% identity remains eligible. Collapse only byte-identical processed models and otherwise preserve deterministic diversity. |
| Single-component MR | Ask Phaser to search all requested `n` copies jointly. Keep sequential same-component placement as an explicit rescue route only. |
| Score waves | Joint-A primary: strict total `LLG > 100 OR TFZ > 10`; fallback: strict `LLG > 50 OR TFZ > 5`. Fixed-A/joint-B uses incremental `delta_LLG` from the parent and B-specific TFZ under the same numeric tiers. Scores rank but never delete or establish identity. |
| Refinement | Run one identical brief refinement and maps for every packed full or partial state before composition review, with one immutable Free-R mapping per dataset. |
| Heteromer seed | Automatically expand every refined packed A state whose ASU-completion assessment is unresolved: component-partial states qualify directly, while component-full states require observed residual-content evidence. No human A-seed checkpoint is required, but final composition review remains human. |
| Heteromer scope | Exactly two distinct catalogue sequence groups `nA+mB`. Arbitrary three-component search and AF3 complex prediction are out of scope. |

## Schema-v2 and execution architecture

### Public contracts

Add new records rather than changing v1 result semantics in place:

- `ComponentSpec`: component label, sequence group, model and digest, requested
  copy count, error/identity evidence, role, and provenance;
- `CompositionMatthewsHypothesis`: component stoichiometries, combined sequence
  mass, solvent/Matthews values, physical status, and rank;
- `CompositionHypothesis`: crystal and symmetry identity, canonical component
  set, search component, optional fixed parent, evidence wave, and resource
  profile;
- `MrPlacementResult`: requested and placed counts per component, packing, raw
  parent and child LLG/LLGI, incremental `delta_LLG`, total and component-
  specific TFZ/VRMS where emitted, full/partial/no-placement class, artefact
  checksums, warnings, and execution status;
- `ResidualContentAssessment`: placed mass, remaining broad mass interval,
  connected positive difference-density evidence, unexplained SDS bands,
  native-complex compatibility, evidence availability, and
  `resolved/suspected/unknown` status without an identity claim;
- `SolutionState`: content-addressed parent/child state with component-to-chain
  mapping, coordinates, MTZ, refinement/maps, residual-content evidence,
  component completeness, ASU-completion assessment, budgets, and terminal
  status; and
- `BriefRefinementResultV2`: refinement evidence bound to a complete solution
  state and immutable Free-R mapping.

`SolutionState` must keep `placed`, `packed`, `refined`, and
`scientifically_supported` separate. Packing or a Matthews-expected count can
never create scientific support by itself.

Composition identity is canonical and ignores A/B search order. Placement
attempt identity retains the parent and search direction, so A-to-B and B-to-A
evidence remain separately inspectable.

The immutable review sequence is `composition` followed by
`sequence_candidate`. Composition review may approve, retain as an alternative,
defer, or abstain without mutating the structural `SolutionState`. Only approved
or retained composition alternatives enter per-component `sequence_from_map`
or equivalent sequence discrimination. That stage emits exact-group,
family-level, ambiguous, abstained, no-evidence, and typed parse/tool-failure
identity decisions with evidence pointers. Reportable identity and truth-side
false-assignment evaluation derive from those emitted decisions, never from a
case descriptor.

Crystal and pipeline configuration move to schema 2.0. Catalogue, database,
and Phenix manifests retain schema 1.0 unless their own semantics change. A
deterministic v1-to-v2 migration handles operator-authored crystal/config
inputs; historical results are never rewritten.

Each native-PAGE observation has an immutable observation ID, apparent mass in
kDa, positive absolute uncertainty in kDa, method/condition, band role,
replicate, and notes. Missing native-PAGE data are neutral. Native PAGE is an
apparent solution-complex/oligomer prior and is never used as crystallographic
ASU total mass or physiological-assembly proof.

The SDS and score state machine is explicit:

1. execute the SDS-compatible wave; when SDS data are absent, every candidate
   belongs to this neutral first wave;
2. classify packed joint-A results against strict `LLG > 100 OR TFZ > 10`;
3. only when no packed primary result exists, activate strict
   `LLG > 50 OR TFZ > 5` on the retained results;
4. open the SDS-mismatched candidate wave only when neither active tier yields
   a packed result, unless an explicit reviewed override requests it; and
5. retain all executed attempts, raw scores, and wave transitions.

For a fixed-A/joint-B attempt, steps 2--3 use `delta_LLG` relative to the fixed
parent and the B placement TFZ, not total child LLG dominated by A. Missing SDS
bands are never assigned uniquely to A or B.

### Nextflow and cache boundary

- Every independent catalogue, crystal, hypothesis, parent state, partner
  attempt, refinement, and finalist is a Nextflow channel item.
- Every process receives one complete typed tuple; singleton queue channels are
  not paired with multi-item fan-outs.
- Database-backed queries remain deterministic sequence/residue-bounded
  batches rather than one database load per sample.
- Python executes one task or deterministically aggregates completed typed
  records. It must not run scientific thread/process pools.
- Cache identity includes raw input checksums, database inventory, component
  and model digests, parent state, selected MTZ dataset, space group and
  resolution, Free-R mapping, adapter/source identity, Pixi lock, and verified
  external executable identity.
- Stored bundles are reusable only after complete nested checksum validation.
- Dependent fixed-parent placement is sequential within one state chain;
  independent chains fan out through Nextflow and Slurm.

### V2.3 — Automatic partial-state expansion

Every packed A state receives a typed ASU-completion assessment after the
standard brief refinement. A state becomes an automatic partner-search seed
when it carries complete coordinate/MTZ/component/checksum provenance and
either:

- is component-partial (`1 <= placed A < requested A`); or
- is component-full but observed residual-content evidence is `suspected` from
  controlled map evidence, a physically plausible remaining broad mass
  interval, unexplained SDS bands, or native-complex incompatibility with A
  alone.

These are search-eligibility triggers, not claims that A or a heteromer is
scientifically supported. Descriptor/truth labels cannot create the trigger.

- Every qualifying parent remains eligible without a human A-seed checkpoint.
- The actual placed A count becomes `n` in the child composition.
- Parent states deferred by the job cap remain retained and explicit.
- Deterministic round-robin selection spans parent, B group, provider, model
  variant, and stoichiometry.
- Component-full states with `resolved` or `unknown` residual assessment do not
  branch automatically; this bounded trigger remains an explicit v0.2
  sensitivity limitation.

Gate: expansion, canonical deduplication, cap fairness, and complete parent
retention pass multi-parent tests and cached resume. An end-to-end 6RTZ `1+1`
case must demonstrate a component-full A state entering partner search from
observed residual evidence.

### V2.4 — Fixed-A, joint-B heteromer search

For every selected A parent:

1. enumerate distinct B sequence groups with usable models;
2. enumerate physically possible `nA+mB` hypotheses from combined sequence
   mass;
3. retain up to four in-window `m` hypotheses per B, then rank deterministically
   by remaining SDS-band compatibility, native-complex plausibility, combined
   Matthews feasibility, B model accuracy/completeness, and structural/source
   diversity before the 25-job-per-crystal/wave partner cap;
4. fix all placed A coordinates with their original uncertainty and ask Phaser
   to place all requested `m` B copies jointly;
5. preserve A unchanged when B fails;
6. retain partner-full, partner-partial, no-partner, deferred-budget, and
   execution-failure states;
7. briefly refine and map every packed child; and
8. publish a human composition checkpoint with supported, ambiguous,
   parent-only, unresolved, and failed outcomes.

Record every generated, selected, tested, and cap-deferred B/stoichiometry
hypothesis and round-robin decision. Rank partner placement with B-specific TFZ
and incremental `delta_LLG` relative to A; retain but do not use total child LLG
as standalone partner evidence.

The B adapter must accept an independent model and multi-sequence composition.
It must never reuse A coordinates as B's search model.

Gate: a fixed adapter-isolation smoke uses a checksum-reviewed A parent from
6RTZ HisF/HisH and recovers B without depending on upstream discovery. Run both
A-to-B and B-to-A directions; their canonical composition IDs must match while
attempt IDs and evidence remain distinct.

## Local/CI/Viper loop

Every material increment follows one closed loop:

1. read the newest development-journal entry and inspect the single owned run;
2. add the smallest reproducing regression, contract test, or vertical slice;
3. implement only that increment;
4. run focused checks and one complete `pixi run --locked check`;
5. inspect status and diffs and create one coherent clean commit;
6. after authorisation, push once and watch exactly one CI run;
7. deploy only checksum-reviewed controller/dispatcher changes;
8. stage an exact pushed SHA through one fixed, separately reviewed profile;
9. submit and monitor one owned job through the reviewed wrapper only;
10. retrieve bounded logs and collection at terminal state before editing;
11. classify scientific no-hit, software defect, or infrastructure failure;
12. for a software defect, add one focused regression, apply the minimal fix,
    rerun the locked gate and one CI run, then replay the unchanged profile; and
13. append only material evidence and the exact next start to the journal.

No raw SSH, scheduler command, file transfer, generic case/path/Phaser option,
implicit cancellation, or cleanup becomes part of a routine profile.

New fixed profiles are introduced only as their preceding local gate passes:

- `v02-joint-smoke`;
- `v02-component-slice`;
- `v02-component-matrix`;
- `v02-heteromer-adapter-smoke`;
- `v02-heteromer-slice`;
- `v02-heteromer-matrix`; and
- `v02-heteromer-holdout`.

Each profile changes local CLI enums/stage commands, remote validation,
resource mapping, job scripts, bounded collection, schemas, fake-site tests,
dispatcher integration tests, wrapper syntax, and deployment checksums as one
reviewed surface.

Initial resources are a 2-CPU/8-GB Nextflow driver, 8-CPU/16-GB Phenix workers,
the existing 32-CPU/16-GB MMseqs2/Foldseek batch workers, a 24-hour per-job
ceiling, and a target of no more than four simultaneous Phenix workers until
terminal evidence supports a change. The Viper project ceiling remains 64
CPUs/192 GB. The Phenix concurrency, queue-size, and submission-rate targets
are not claimed as enforced until corrected executor configuration and a real
smoke prove them.
