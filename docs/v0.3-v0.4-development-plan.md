## Engineering rule: fix clear defects directly

For an evident defect, make the smallest coherent correction immediately. Do not
preserve broken behaviour for backward compatibility or add aliases, alternate parsers,
fallback branches, feature flags, or diagnostic frameworks to accommodate it. Update
current callers, contracts, examples, and tests together when semantics change;
immutable release artifacts preserve history.

Use existing checks and observed execution evidence where sufficient. A new regression
is justified by a meaningful scientific invariant, a non-obvious boundary, or a
demonstrated recurring failure mechanism that existing checks miss. It is not an
automatic prerequisite for every bug fix. A wrong constant name should receive a
corrected name; an identified profile timeout mismatch should receive the bounded
timeout correction and existing staging checks. Neither needs a new compatibility path
or permanent diagnostic subsystem.

This rule applies to every test/acceptance item below: the item names the behaviour to
verify, not a requirement to create another test file or matrix. Keep scientifically
necessary command/parser/failure tests for new adapters. Replace tests that enforce
superseded or erroneous policy rather than bending the implementation to retain them.
Run broad gates at named integration/release boundaries, not after every trivial change.

## Why the reassessment changes v0.4

The source applies a global 25-mapping coordinate-acquisition limit before
crystal-specific selection. The retained private audit found that this excluded most
groups with eligible structural hits. Groups unacquired because of that limit are
scientifically different from groups without eligible hits or without usable models. A
combined unavailable-model count must not erase these distinctions. Private catalogue
counts and per-crystal results remain in their owned evidence, not this roadmap.

This demonstrates an acquisition bottleneck before crystal-specific MR ranking. It does
not prove that the undisclosed true protein was excluded. Likewise, 25/25/25
reproducible tasks demonstrate execution of the chosen cohort, not full-catalogue target
recovery. The first-copy task count and number of distinct tested proteins must be
reported separately.

The v0.4 critical path now includes:

1. A full candidate/template planning inventory and explicit acquisition deferrals.
2. Crystal-specific preliminary selection, followed by bounded coordinate acquisition
   for the union of those choices.
3. Target-aware model preparation and evaluated conditional first-copy feasibility.
4. A fixed brief-refinement pass over valid retained MR placements before final
   candidate filtering and A review, with Matthews retained as a physical prior (BR01).
5. Bounded access to new candidate groups after a complete weak first batch; one weak
   packed pose cannot close exploration.
6. Known-structure recovery from complete catalogues with observed masses and target
   labels hidden from selection.
7. A qualified original-sequence-model AFDB Foldseek fallback after experimental
   template routes, with explicit model confidence and coordinate-based similarity (AF01).
8. Exact-sequence AlphaFold-model MR for retained finalists before final candidate
   assessment, even when the initial model was experimental (AF02).

Here, mass-blind means no observed gel mass, mass window, supervisor identity hints, or
inferred target labels. Sequence-derived catalogue masses remain legitimate inputs.
Ribosomal and other highly conserved proteins remain valid candidates; fixing early
narrowing does not justify excluding them by annotation.

The full Pro review's original 30 findings remain in scope, including failure
accounting, cache/resume integrity, Free-R, path handling, runtime immutability, beam
diversity, early gates, setup, and atlas maintenance. The new acquisition and expansion
defects must be repaired before performance qualification of the successor method.

## Scientific-method references

BR01 reuses the project's one-cycle protocol as a diagnostic, not a claim that one cycle
completes structure refinement. The [official Phenix MR
FAQ](https://phenix-online.org/documentation/faqs/mr.html) explains target-aware model
editing, incomplete ASU limitations and use of original reflection data. The
[phenix.refine reference](https://phenix-online.org/documentation/reference/refinement.html)
specifies refinement settings and held-out-reflection safeguards. Neither source
validates automatic protein identity or a catalogue-wide Rfree selection threshold.

Oeffner, R. D., Afonine, P. V., Millan, C., Sammito, M., Uson, I., Read, R. J., and
McCoy, A. J. (2018). On the application of the expected log-likelihood gain to decision
making in molecular replacement. Acta Crystallographica D: Structural Biology 74,
245-255. [DOI: 10.1107/S2059798318004357](https://doi.org/10.1107/S2059798318004357);
[author manuscript and abstract](https://escholarship.org/uc/item/5tf5w186).

This supports conditional eLLG for search planning and model pruning. It does not
validate a protein-identity score, a new rejection threshold, or success on the unknown
inputs. The proposed adapter still requires supported-runtime command/parser/failure
fixtures and real Phenix qualification.

The solvent-window distinction is supported by Weichenberger, C. X., Afonine, P. V.,
Kantardjieff, K., and Rupp, B. (2015). The solvent component of macromolecular crystals.
Acta Crystallographica D: Biological Crystallography 71, 1023-1038. [DOI:
10.1107/S1399004715006045](https://doi.org/10.1107/S1399004715006045); [publisher
article, section 2](https://journals.iucr.org/d/issues/2015/05/00/jm5003/index.html).
The reported conventional range has exceptions; a configured cutoff alone cannot
establish physical impossibility.

## Validation and release discipline

Fix clear defects directly, using existing focused checks where sufficient and new tests
only for meaningful uncovered invariants. Use small real-tool controls when the relevant
slice is runnable. Run the full locked gate at named integration/release points; require
exact-source CI and appropriate fixed-HPC evidence before qualification. For v0.3, close
FS-G1 and RF-G1-RF-G4 explicitly before tagging; future v0.4 work cannot substitute for
a pre-tag gate. Historical CI totals and the Pro review's isolated test run are evidence
about those checks, not acceptance of the new cases or changed production ranking.

For execution-only changes, compare normalised scientific records and required artifacts
after excluding intentionally variable event metadata. For resource/tool-parallelism
changes, establish numerical tolerances from supported tool behaviour and repeatability,
and compare decisions as well as values. Do not widen tolerances after observing an
inconvenient result.

Include full-inventory conservation, cross-crystal acquisition unions, selected objects
shared across mappings, lower usable hits, actual versus unique-protein task counts,
weak-packed/null-wave expansion, bounded acquisition/MR budgets,
multi-crystal/multi-catalogue cardinality, sibling isolation, malformed/empty providers,
missing required outputs, review mutation, selected-model/MTZ/Free-R/runtime mutation,
offline execution, and final archive reconstruction. Existing cache namespaces and
review packages must not be silently reused across incompatible semantics.

Retain identity/model/evidence separation, raw metrics, catalogue-bound identities,
complete model universes, truthful no-hit/failure/deferred states, human checkpoints,
one-copy requests with explicit observed tNCS placement, sequential reviewed copy
continuation, and bounded composition. Preserve the current
five-A-state/three-composition-parent distinction, 25 attempts per depth, 100
additional-component attempts, and provisional depth-four-through-six claims unless
separately changed through the scientific approval process.

Keep scientific source changes on the authorised main development line, use coherent
commits, and update callers, schemas, examples, tests, documentation, and cache
invalidation together. Remote benchmark profiles and budgets require the existing
explicit approval; this plan schedules no jobs and authorises no deployment.
