## Authoritative engineering state

### One public application

The installed research package exposes one public command:

```bash
genome-to-diffraction --help
```

The repository-specific HPC client remains an internal source-checkout
validation tool invoked through its locked Pixi task. It is not a second public
research application and must not become one.

### Execution ownership

The active workflow uses:

- Python for contract validation, deterministic scientific records, ranking,
  review packages, and report assembly;
- Nextflow DSL2 for independent scientific task fan-out, dependency ordering,
  retries, caching, and publication;
- Slurm for aggregate admission and concurrency; and
- file-based human decisions at every scientific checkpoint.

Independent candidates, crystals, models, and composition attempts are
Nextflow channel items. Python and shell wrappers must not introduce nested
thread pools, process pools, candidate loops, or scheduler authorities.

The fixed Slurm profile resolves `executor.queueSize = 0`, which is Nextflow's
unlimited task-monitor capacity. No global, profile, or process-local
`maxForks` cap may throttle the scientific fan-out. Slurm decides when emitted
tasks start.

### Fail-closed contracts

Current scientific execution is content-addressed. A run binds its exact:

- Git commit and tree;
- Pixi lock and helper revision;
- execution-policy checksum;
- catalogue, crystal, database, and provider artefacts;
- Phenix manifest and executable checksums;
- adapter versions;
- human-review packages and decisions; and
- task, result, and output checksum inventories.

Missing, malformed, stale, cross-run, cross-crystal, duplicated, symlinked, or
checksum-mismatched state fails before promotion. Failed and cancelled runs are
diagnostic only and cannot become scientific or cache authority.

## Candidate-screen policy

### Complete Matthews ranges

Every catalogue candidate receives the complete finite ASU copy range derived
from the unit-cell/space-group volume, full catalogue-sequence mass, and the
configured solvent bounds. The active line has no configured scientific copy
ceiling.

Ordering uses the checksum-pinned 2013 MATTPROB protein reference:

- a resolution-conditioned empirical solvent-density estimate; multiplied by
- the published empirical homooligomer copy-frequency prior `P(n)`.

This is a soft physical ranking prior, not an identity probability. A low or
zero prior does not remove a physically possible state.

See [Dynamic, resolution-aware Matthews priors](matthews-probability.md).

### One-copy initial MR

The candidate hypothesis retains its Matthews expected copy count, but every
initial MR command requests exactly one search copy. There is no joint-copy
mode, four-copy admission filter, or hidden static copy limit. At most 25
ranked hypotheses are retained per crystal for this first screen.

Additional copies are placed only after human approval and only one at a time.
Every supported and unsupported intermediate copy state must be retained.

### Independent review ranks

The A review publishes:

- a Matthews rank from physical status and empirical prior;
- an MR rank from execution status, packing, requested/observed copies, LLG,
  and TFZ;
- absolute rank discordance; and
- the raw metrics and warnings needed to inspect either ordering.

The combined review-priority ordering is not calibrated confidence and cannot
establish identity. High rank discordance is expected to guide, not replace,
human review.

### Translational-NCS boundary

Phaser `MR_AUTO` may infer a translational-NCS group and expand a requested
one-copy search into a coupled placement. Such a result must be labelled with
the requested and observed copy counts. It is not a strict one-copy result.

Before continuing an affected crystal, the reviewer must explicitly choose
whether to accept the coupled tNCS state or require a strict non-tNCS
successor. The workflow must never infer that choice.

## Dynamic MR resources

Each MR hypothesis receives a deterministic resource plan from:

```text
reflection_count
  * (moving_model_atoms * searched_copies + fixed_component_atoms)
  * min(symmetry_multiplicity, 8)
```

The current fixed-site first-attempt tiers deliberately favour elapsed time:

| Tier | CPUs | Memory | Time |
| --- | ---: | ---: | ---: |
| standard | 8 | 32 GB | 24 h |
| heavy | 12 | 48 GB | 36 h |
| very heavy | 16 | 64 GB | 48 h |

One retry is permitted only for a classified resource or temporary
infrastructure failure. `task.attempt` scaling is linear and capped at 16 CPUs,
64 GB, and 48 hours. Scientific no-hit, parse failure, malformed evidence, and
contract failure are not resource-retry events.

The MR command binds `phaser.keywords.general.jobs` to the allocated task CPU
count. Resource identity is operational evidence and invalidates the execution
cache without changing scientific hypothesis identity.

See [Dynamic Phaser resource allocation](mr-resource-allocation.md).

## Validation strategy

### Local development

Use focused tests while iterating. Unit and integration suites use
`pytest-xdist` across visible local CPUs; embedded Nextflow tests remain in one
lock-safe group. Serial tasks remain available for reproducing order-sensitive
failures.

Useful focused gates are:

```bash
pixi run --locked format-check
pixi run --locked lint
pixi run --locked typecheck
pixi run --locked test-unit
pixi run --locked test-contract
pixi run --locked test-integration
pixi run --locked docs-check
pixi run --locked check-fast
```

The named complete boundary is:

```bash
pixi run --locked check
```

Run it at an exact scientific integration, deployment, or release point, not
after every small edit.

### CI

GitHub Actions has six parallel lanes:

- quality;
- unit;
- integration;
- Nextflow core;
- scientific stubs A; and
- scientific stubs B.

Their union is contract-tested against every complete-gate leaf. CI is needed
for the exact commit selected for deployment or release, not for every local
documentation or exploratory commit.

- unique task identities and native scheduler jobs;
- all first attempts completed without a resource retry;

This is execution and screening evidence. It is not an identity claim and it
